The Unified Project iOS Cross-Functional Team: OpenShift Cluster Build Admins, Day-2 SRE & Automation Engineers, VMware Operations, Storage, Network, Datacenter Infrastructure, and the MTV Custom Tooling Team.
Challenge
We set out to migrate mission-critical enterprise workloads from legacy VMware environments to OpenShift Virtualization under strict maintenance windows and zero-data-loss SLAs.
Traditionally, our infrastructure lived in organizational and technical silos: physical datacenter hardware, network fabric, enterprise storage, legacy hypervisors, and migration tooling were handled by separate teams with different priorities, tools, and queues. We quickly realized that any single friction point—a VLAN mismatch, a storage throughput bottleneck, an ESXi host communication error, or an automated pipeline stall—could halt our cutovers and put production systems at risk if we didn't work as a single unit.
People and collaboration
Instead of throwing tickets over the wall, we decided to act as one cohesive team with a shared mission:
 * Bridging Hypervisors & Platforms: Our VMware admins and OpenShift build admins paired up daily, mapping out low-level storage profiles, guest OS quirks, and compute footprints together before running any cutovers.
 * Building Shared Reliability: Our SREs embedded directly with the Network, Storage, and Datacenter teams. Together, we engineered end-to-end telemetry and automated pre-flight checks to ensure hardware interfaces, node fabrics, and storage classes were hardened prior to migration.
 * Co-Developing in the Trenches: The custom MTV tooling team joined live cutover calls with our operations engineers. When an edge case cropped up, developers and operators worked side by side to push real-time enhancements and fix automation hooks immediately.
 * True Shared Ownership: We adopted a blameless culture across organizational boundaries. An issue during a migration wave was never treated as "the network's problem" or "the platform's fault"—it was a collective challenge that we triaged, solved, and automated away together.
Outcome
 * Seamless Mass Migrations: We turned what could have been a manual, high-risk process into a scalable, automated pipeline, drastically reducing cutover time per VM wave and meeting every maintenance SLA without data loss.
 * Automated Day-2 Operations: By combining SRE automation with deep domain expertise, we eliminated hundreds of manual configuration steps for post-migration validation and day-2 health checks.
 * A United Infrastructure Community: We broke down long-standing silos between traditional infrastructure engineering and modern platform SREs, proving that we can manage bare-metal, containers, and virtual machines as one unified platform family.
Behaviour worth repeating
 * Co-Ownership Over Handoffs: Swarming complex infrastructure projects as a single multidisciplinary tiger team instead of relying on ticket-based handoffs.
 * Fix Once, Automate Forever: Turning every field issue or edge case into an automated MTV hook, playbook, or validation check so we never solve the same problem twice.
 * Unified Pre-Flight Discipline: Validating all layers—from physical datacenter links to cluster storage and hypervisor configs—before initiating workload migrations.
